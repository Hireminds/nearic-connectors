# Общий коннектор Nearic и адаптер Codex

- **Ветка** — `001-common-connector`
- **Дата** — 24 ноября 2026 г.
- **Статус** — согласована владельцем 24 ноября 2026 г. (поведение ревизии `103cc99`)
- **Цель итерации 1** — владелец проверяет связь с зарегистрированным BOX из выбранного существующего разговора Codex.

## Пользовательские сценарии и проверки

### 1. Установить плагин Desktop и подключить BOX (P1)

Владелец находит Nearic по ссылке из инструкции выпуска, устанавливает плагин через поддерживаемый интерфейс Desktop и запускает вход в Nearic из плагина. После подтверждения доступа он возвращается в существующий разговор A, выбирает BOX из зарегистрированных в своём аккаунте, видит выбранные BOX и разговор и подтверждает привязку.

**Независимая проверка.** В чистом профиле Desktop с уже существующим разговором A установить плагин и привязать тестовый BOX.

1. При успешном входе и подтверждении владелец видит, что BOX привязан к A. История A доступна, и пользователь продолжает тот же разговор.
2. При отмене входа или подтверждения новая привязка отсутствует. Если у аккаунта нет зарегистрированных BOX, пользователь узнаёт об этом и может вернуться после регистрации.
3. Если клиент не может подтвердить контекст A, Nearic объясняет, почему привязка недоступна. Ввод названия или ID в сообщение не даёт доступ.

### 2. Установить пакет на удалённом хосте и переключить BOX (P1)

Владелец по инструкции выпуска устанавливает консольный пакет Nearic на хосте, где запускает Codex CLI по SSH. Он запускает вход из пакета, открывает предложенную ссылку в браузере на другом компьютере, подтверждает доступ к Nearic и получает итог в терминале. Затем он выбирает существующий разговор B, доступный в Codex CLI, и подтверждает переключение выбранного BOX с A на B.

**Независимая проверка.** Использовать удалённый хост без браузера, отдельный компьютер с браузером, существующий разговор B и BOX с действующей привязкой к A.

1. После входа в браузере владелец может завершить настройку на удалённом хосте без переноса постоянных учётных данных и без браузера на этом хосте.
2. После подтверждения B получает доступ к BOX. Новый запрос из A по прежней привязке отклоняется. Если BOX ещё не привязан, эта же процедура создаёт первую привязку.
3. Отмена, истечение срока входа или отказ при переключении до его подтверждения на стороне сервиса сохраняют A. При потере подтверждения пользователь может узнать, какая привязка сейчас действует.

### 3. Запросить живой статус и проверить отзыв доступа (P1)

Из привязанного разговора владелец просит проверить BOX. Единственный проверочный инструмент получает ответ устройства на текущий запрос и сообщает версию прошивки и время работы после загрузки. Владелец может отозвать доступ подключённой интеграции к Nearic.

**Независимая проверка.** В любом поддерживаемом клиенте с привязанным BOX вызвать проверку при доступном устройстве, при обрыве его связи, после восстановления и после отзыва доступа.

1. При доступном BOX пользователь получает свежий ответ с данными этого устройства. При потере связи или ожидании сверх установленного срока пользователь видит соответствующую причину отсутствия свежего ответа. После восстановления новый запрос снова может завершиться успешно.
2. После подтверждённого отзыва новый запрос от этой интеграции возвращает отказ в доступе даже при доступном BOX. BOX сохраняет регистрацию в аккаунте.
3. Если ответ на уже начатую проверку приходит после переключения, он относится только к исходным запросу и разговору. Если этот запрос уже завершён по сроку ожидания, поздний ответ не превращает его в успешный.

### Пограничные случаи

- BOX из другого аккаунта недоступен для выбора и привязки. При отзыве между выбором и подтверждением сервис отказывает в операции.
- Два подтверждения переключения одного BOX не могут оставить два действующих разговора. Повтор после потери ответа позволяет определить действующую привязку без повторного переключения, если первоначальное действие уже завершилось.
- При отмене, истечении срока или прерывании входа пользователь видит итог и может заново начать вход. Временный сбой запроса статуса сам по себе не снимает привязку.

## Требования

### Функциональные требования

- **FR-001.** Desktop и удалённый CLI используют одно ядро для авторизации Nearic, привязки, переключения, отзыва и обработки статуса. Первый адаптер предназначен для Codex. Каждый клиентский адаптер отвечает за получение контекста разговора и адаптацию установки и взаимодействия с хостом.
- **FR-002.** Инструкция выпуска показывает, где пользователю получить официально распространяемые плагин Desktop и консольный пакет, какие версии клиента и хоста поддерживаются и как проверить готовность установки. Пользователь завершает установку из поставляемых артефактов и видит, доступна ли интеграция в его клиенте.
- **FR-003.** Пользователь начинает авторизацию в плагине Desktop или в установленном пакете на удалённом хосте. Во втором случае подтверждение проходит в браузере другого компьютера, а итог доступен в той же терминальной процедуре. Авторизация относится к аккаунту Nearic и выбранному подключению агента. Ввод секретов в разговор не требуется.
- **FR-004.** После авторизации пользователь выбирает зарегистрированный в своём аккаунте BOX и явно подтверждает конкретный существующий разговор. Адаптер получает проверяемый контекст от хоста. Доверенная сторона проверяет контекст и полномочия для привязки и каждого вызова статуса. Если подтверждения контекста нет, операция отклоняется.
- **FR-005.** У BOX может быть один действующий разговор. При переключении сервис заменяет привязку только при успешном подтверждении. С этого момента новые вызовы принимаются только из нового разговора при наличии доступа. Результаты начатых вызовов сохраняют исходную адресацию.
- **FR-006.** Владелец может отозвать доступ подключения агента. С момента подтверждения отзыва сервис отклоняет его новые операции, включая вызовы с ранее выданным доступом. Для дальнейшей работы отозванному подключению требуется новый вход и подтверждение разговора. Регистрация BOX и его доступ к сервису сохраняются.
- **FR-007.** Доступен один проверочный инструмент живого статуса. Успех означает ответ привязанного BOX на этот вызов с версией прошивки и временем работы. Ранее полученный ответ не считается успехом, даже если устройство недавно было на связи.
- **FR-008.** Пользователь может различить отказ в доступе, отсутствие действующей привязки в текущем разговоре, недоступность устройства и истечение срока ожидания ответа. Если состояние связи неизвестно, результат сообщает об истечении ожидания без утверждения об отключении BOX.

### Сущности

- **BOX** — устройство, зарегистрированное в аккаунте Nearic.
- **Подключение агента** — отзываемый доступ интеграции к аккаунту Nearic.
- **Разговор** — существующая сессия, которую клиент может подтвердить для операции.
- **Привязка** — действующая связь BOX с подтверждённым разговором и подключением агента.
- **Проверка статуса** — запрос к BOX с исходным разговором и собственным сроком ожидания.

## Критерии успеха

- **SC-001.** На чистом профиле Desktop и чистом удалённом SSH-хосте пользователь проходит оба пути установки и входа по инструкции выпуска. Каждый путь заканчивается привязкой к разговору, созданному до установки. Для CLI браузер запущен только на другом компьютере.
- **SC-002.** На одном физическом BOX в отдельной сети получен свежий ответ с версией и временем работы из A в Desktop и из B в CLI после переключения. Запрос из A после переключения отклонён. При отменённой попытке переключения A сохраняет доступ. Задержанный ответ на запрос A не появляется в B.
- **SC-003.** На каждом клиенте подтверждены различимые результаты для отзыва доступа, отсутствия привязки, известной недоступности BOX и истечения срока ожидания. После восстановления связи при действующем доступе проходит новый запрос. Запрос с неподтверждённым или подменённым контекстом отклонён.
- **SC-004.** На ревью поставки подтверждено, что оба пути используют одну реализацию операций Nearic. В протоколе приёмки указаны версии Desktop, CLI, сервиса и прошивки, условия запуска, фактический результат и ограничения каждого прогона.

## Допущения и границы

- У владельца уже есть аккаунт Nearic, зарегистрированный BOX и доступ к существующему разговору на каждом проверяемом клиенте. Для переключения достаточно двух разных разговоров. Перенос истории между хостами не входит в итерацию.
- Для поставки нужны версии Nearic Service и прошивки с поддержкой согласованных операций. В итерацию коннектора входят установка интеграции, вход, адресация, управление доступом и один живой статус. Регистрация и настройка BOX, обновление прошивки, голос, управление экраном и адаптеры других агентов за пределами итерации.
- Источник дистрибуции, формат пакета, язык, API и способ передачи доверенного контекста выбираются в техническом плане. Спека задаёт поведение установки для пользователя и условия приёмки.

## Возможности Codex и проверки совместимости

### Что подтверждено первичными источниками

- **Desktop.** OpenAI описывает установку из собственного каталога плагинов и запуск встроенного шага настройки в существующем разговоре, если установка начата там. Для серверов, настроенных на хосте Codex, документированы подключение инструментов, OAuth и конфигурация серверов через плагин. [Упаковка и установка плагина](https://developers.openai.com/plugins/build/plugins), [MCP в Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).
- **CLI на удалённом хосте.** CLI документирует продолжение сохранённого разговора через `codex resume` и отдельный вход в HTTP MCP-сервер через `codex mcp login --no-browser`, где браузер открывает выданный адрес, а терминал принимает адрес возврата. Наличие этих команд также проверено в справке CLI 0.162.0. Вход в аккаунт Codex на хосте описан отдельно. [Команды Codex CLI](https://learn.chatgpt.com/docs/developer-commands?surface=cli), [Авторизация Codex](https://learn.chatgpt.com/docs/auth).
- **Контекст.** События hooks содержат идентификатор сессии, а App Server умеет читать и возобновлять сохранённые разговоры. Это точки для технической проверки. Документация этих интерфейсов сама по себе не устанавливает, какие доверенные сведения получит Nearic при каждом вызове инструмента. [Codex Hooks](https://learn.chatgpt.com/docs/hooks), [Codex App Server](https://learn.chatgpt.com/docs/app-server).

### Что проверить на реальных клиентах

- **Desktop.** На выбранной версии и с выбранным способом распространения пройти установку, вход и подключение инструментов Nearic в уже существующем разговоре. Проверить повторное открытие разговора, необходимость перезапуска приложения и требования настроек рабочей области.
- **CLI.** На выбранной версии и чистом удалённом хосте подтвердить установку пакета, вход Nearic с отдельного компьютера, продолжение нужного разговора и вызов после повторного подключения по SSH. Проверить отмену и истечение срока входа.
- **Оба клиента.** Доказать, что Nearic может проверить адресацию при привязке и при вызове инструмента, включая переключение между двумя открытыми разговорами, подмену заявленного контекста и продолжение сессии. Совместимость подтверждается только после прогона; полный путь до физического BOX проверяется по критериям успеха.
