# Исследование интеграции Codex

## Адрес существующего разговора

**Предложение.** Запускать Nearic как локальный stdio MCP от хоста Codex. Брать строковый `params._meta.threadId` из входящего `tools/call` и выделять её в собственный тип контекста до разбора аргументов операции. Ни имя разговора, ни `sessionId`, ни последний чат проекта не заменяют `threadId`. Для SSH владелец открывает сохранённый разговор через `codex resume` и запускает настройку в этом разговоре. Desktop использует активный повторно открытый разговор. В обоих клиентах выбор владельца подтверждается отдельно.

В исходниках Codex CLI 0.162.0 ядро заполняет метаданные из `sess.thread_id` и отдельно добавляет `sessionId`. MCP-клиент передаёт метаданные отдельно от аргументов. Это подтверждает кандидат на уровне исходников конкретной версии. Накладка SDK, переговоры о версии MCP, обычный вызов и доступные режимы инструмента требуют проверки на каждом хосте. [Исходники ядра](https://raw.githubusercontent.com/openai/codex/rust-v0.162.0/codex-rs/core/src/mcp_tool_call.rs), [исходники MCP-клиента](https://raw.githubusercontent.com/openai/codex/rust-v0.162.0/codex-rs/rmcp-client/src/rmcp_client.rs).

App Server предоставляет чтение и возобновление чатов и экспериментальные динамические инструменты для собственного клиента протокола. Для штатного Desktop-плагина выбран stdio. Hooks дают `session_id` и зависят от возможностей хоста и доверия пользователя. Они не выбраны источником точного адреса в первом варианте. Вход в аккаунт OAuth отдельно доказывает право пользователя, но сам по себе не адресует разговор. [App Server](https://learn.chatgpt.com/docs/app-server), [Codex Hooks](https://learn.chatgpt.com/docs/hooks).

## Авторизация

**Предложение.** Оба входа запускают одно ядро OAuth Device Authorization Grant Nearic. В SSH `nearic auth login` показывает адрес и короткий пользовательский код. Владелец открывает браузер на другом компьютере и подтверждает код и доступ. Терминал ждёт результат с соблюдением `interval` и `slow_down`, завершает ожидание при отказе, отмене либо истечении. Desktop запускает тот же поток из шага настройки плагина. В коде для пользователя и в ответе инструмента отсутствуют токен и секретный `device_code`. [RFC 8628](https://www.rfc-editor.org/rfc/rfc8628).

`codex mcp login --no-browser` документирован для HTTP MCP и просит вернуть полный адрес переадресации в терминал. Это отдельный кандидат при смене транспорта. `codex login --device-auth` авторизует сам Codex. [Команды CLI](https://learn.chatgpt.com/docs/developer-commands?surface=cli), [вход в Codex](https://learn.chatgpt.com/docs/auth).

## Поставка

**Предложение.** В GitHub Releases из одного исходного тега собирать Linux-архив `nearic-<version>-linux-amd64.tar.gz` и Desktop-архив с персональным каталогом, манифестом и бинарником под macOS arm64. Архив Desktop распаковывается в постоянное место. Пользователь подключает локальный каталог по инструкции, перезапускает Desktop и устанавливает Nearic из Plugins Directory. Для пользователя с CLI на том же хосте альтернатива регистрации источника — `codex plugin marketplace add <directory>`, при совпадающем профиле клиента. Пакет Linux распаковывается на SSH-хосте, устанавливает бинарник в пользовательский PATH и регистрирует stdio-сервер в Codex CLI. Обе инструкции проверяют версию и доступность инструментов. Версия для поддержки и обновление из каталога проходят проверку на чистом профиле. Универсальный каталог и менеджер пакетов могут рассматриваться далее. [Упаковка плагина](https://developers.openai.com/plugins/build/plugins), [MCP в Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli), [GitHub Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases).

OpenAI описывает запуск onboarding skill в существующем разговоре, если установка начата там. Это свидетельство о шаге настройки. Доступность локального MCP-инструмента после установки и повторного открытия уже существующего разговора требует отдельного прогона. [Onboarding плагина](https://developers.openai.com/plugins/build/plugins#add-an-onboarding-skill).

## Проверено локально

В Codex CLI 0.162.0 проверена справка `resume`, `plugin marketplace add` и `mcp login --no-browser`. В изолированном пустом профиле App Server той же версии ответил на `initialize` и `thread/list` с пустым списком. Это проверка доступных команд и локального протокола. Прогоны Desktop, MCP-вызова из возобновлённого CLI-разговора, входа Nearic и проверки BOX перечислены в [quickstart](quickstart.md).
