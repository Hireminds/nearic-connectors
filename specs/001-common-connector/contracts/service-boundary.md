# Предложение контракта коннектора и Nearic Service

Один версионируемый HTTPS-интерфейс для обоих способов установки. Имена ниже обозначают операции, а поля показывают минимальное согласуемое содержание. Синтетические значения `install-demo`, `thread-a` и `box-demo` служат только для примеров.

| Операция | Вход | Результат |
| --- | --- | --- |
| Вход | OAuth Device Authorization Grant и доказательство владения ключом при регистрации экземпляра | Разрешение аккаунта, связанное с экземпляром и ключом. Пользовательский код и авторизация имеют ограниченный срок. |
| Начать привязку | Разрешение, подтверждённый адрес текущего разговора, одноразовое доказательство запроса | Одноразовое намерение и ссылка для подтверждения. Владелец видит разговор, выбирает BOX из своего аккаунта и явно подтверждает операцию. Название разговора, если доступно, служит подсказкой. |
| Подтвердить и узнать итог | Подтверждение в браузере под тем же аккаунтом, выбранный BOX, намерение и ожидаемое поколение. Для чтения итога из коннектора — исходное разрешение и доказательство | Текущая привязка и результат намерения. Повтор подтверждения возвращает сохранённый итог без повторного применения. Если привязка уже изменилась, интерфейс позволяет увидеть актуальное состояние и начать новое подтверждение. |
| Запросить статус | Разрешение, подтверждённый текущий адрес и доказательство вызова. При нескольких BOX в этом разговоре — выбранное устройство. Параметры инструмента не содержат адреса или учётных данных | Версия и время работы из текущей операции либо различимый отказ, отсутствие привязки, недоступность или тайм-аут. |
| Отозвать | Подтверждение владельца для конкретного разрешения | Сервис прекращает авторизацию этого экземпляра. BOX остаётся зарегистрированным и подключается самостоятельно. |

## Доказательство адреса

- Адаптер формирует адрес из проверенного канала запуска и метаданных конкретного вызова. Браузер подтверждает выбор владельца для уже зафиксированного адреса. Браузер и модель не задают этот адрес.
- Предложение для сервиса — подписывать запрос ключом экземпляра через HTTP Message Signatures и включать метод, целевой URI, дайджест тела и ограниченные по времени параметры подписи с одноразовым значением. Дайджест связывает доказательство с адресом и содержимым операции. Токен связан на сервисе с тем же ключом. Сервис проверяет подпись, срок, одноразовость и активность разрешения, затем проверяет полномочия. Повтор после потери ответа использует свежую подпись и прежний ID намерения. Параметры профиля подписи и допустимое расхождение часов согласуются до реализации. [RFC 9421](https://www.rfc-editor.org/rfc/rfc9421), [RFC 9530](https://www.rfc-editor.org/rfc/rfc9530).
- Локально проверить две меры вместе. Подписывающий компонент хранит ключ вне доступа агентского sandbox. Локальный вход принимает запросы только из канала, открытого проверенным хостом, с проверкой личности запускающего процесса на уровне ОС. Кандидаты на проверку — отдельный процесс с хранилищем учётных данных ОС и проверкой идентичности запускающего клиента на macOS, отдельный системный principal и ограниченный IPC на Linux. Прямой запуск бинарника из shell, подмена декларации, унаследованный дескриптор и обращение к IPC из агента должны давать отказ. Способ установки этих мер входит в техническое решение после проверки, поскольку дополнительные системные права меняют сценарий установки.
- Ключ зарегистрированной установки удостоверяет делегирование адаптеру. Если достоверность канала к Codex не подтверждается, сервису нельзя обещать проверяемый адрес для этой платформы. Компрометация доверенной ОС или администратора находится за пределами данной границы.

## Живой статус

При принятии операции сервис фиксирует её BOX, поколение и адрес. Только совпавший живой ответ до дедлайна даёт успех. При известном отсутствии связи сервис может сразу вернуть `device_unavailable`. Если известна только просрочка ожидания, результат — `response_timeout`. Отказ по доступу имеет приоритет над диагностикой устройства. Авторизованный запрос из другого разговора даёт `binding_missing` без раскрытия адреса актуального разговора. Отозванный доступ или неподтверждённый контекст дают `access_denied`. Локальное отсутствие метаданных тоже отображается как отказ с причиной отсутствия проверенного контекста.

Если с разговором связаны несколько BOX, пользователь выбирает устройство из доступных в этом разговоре. Коннектор не выбирает BOX молча. Сервис проверяет выбранное устройство по тому же адресу и разрешению.

MCP-поверхность предлагает один проверочный инструмент `nearic_status`. Начало привязки относится к отдельному действию настройки, которое использует ту же подтверждённую адресацию. Управление подтверждением и отзывом происходит с участием владельца. Сервисная граница требует только статуса и управления разрешением и привязкой. Адрес разговора и разрешение агента не передаются BOX.
